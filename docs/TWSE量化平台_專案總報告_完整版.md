# 第零部 名詞解釋

閱讀本報告所需的所有專有名詞,依主題分類。

## A. 績效指標

**報酬率(Return)**
期末價值相對期初的變化百分比。本報告的「總報酬」皆為區間累積報酬,非年化。

**Alpha(超額報酬)**
策略報酬減去基準報酬。例:策略賺 21.5%、0050 賺 6.4%,則 alpha = +15.1%。
**alpha 為正代表跑贏基準**,但需注意基準選擇與期間對齊是否公平。

**最大回撤(Maximum Drawdown, MDD)**
從歷史最高點跌到後續最低點的最大跌幅。例:淨值從 42 萬跌到 31.6 萬,回撤 = -24.9%。
**衡量「最痛的時候有多痛」** —— 實務上比報酬更影響能否堅持執行。

**勝率(Win Rate)**
獲利的平倉交易數 ÷ 總平倉交易數。**單看勝率會誤導** —— 勝率 33% 但每次賺 28%、賠 10%,
整體仍是獲利的。

**獲利因子(Profit Factor, PF)**
總獲利金額 ÷ 總虧損金額。PF = 1 代表打平,> 1.8 一般視為健康。
**小樣本時極不穩定**:只賠過一次的話 PF 會虛高到 10 以上,不具意義。

**夏普比率(Sharpe Ratio)**
年化報酬 ÷ 年化波動度(日報酬的標準差 × √252)。衡量「每承擔一單位風險換到多少報酬」。
> 1 及格、> 1.5 良好、> 2 優秀。本專案採無風險利率 = 0 的簡化算法。

**報酬/回撤比(Return over MDD, 或稱 Calmar 概念)**
總報酬 ÷ 最大回撤絕對值。與夏普互補:夏普看整段路徑的波動,此指標看單一最壞時點。
**兩者同時檢驗,可避免單一指標的偏誤。**

## B. 訊號品質指標

**IC(Information Coefficient,資訊係數)**
**本報告最核心的指標。** 定義為「今天的選股分數」與「未來 N 日實際報酬」的相關係數。

- IC = 0 → 分數與未來報酬毫無關係,等於亂猜
- IC = 0.03 → 業界常見的「有預測力」門檻
- IC = 0.05 以上 → 相當不錯
- IC = 1.0 → 完美預測(現實中不存在)

**具體算法**:某一天全市場 1,200 檔股票各有一個分數,20 天後各有一個實際漲跌幅。
把這兩組數字算相關係數,就是那一天的 IC。871 個交易日各算一次,取平均。

**為什麼 0.03 就算「有預測力」?**
因為股價的短期變動絕大部分是雜訊。能穩定捕捉到 3% 的關聯性,長期複利下就有價值。
但也意味著**單次預測的可靠度極低**,必須靠分散與重複執行才能實現。

**Spearman 等級相關(Spearman Correlation)**
本報告 IC 採用的計算方式。它不比較數值本身,而是比較**排名**。
例:分數第 1 名的股票,實際報酬排第幾名?
**優點**:對極端值穩健(某檔漲 300% 不會扭曲整體結果),適合選股這種「排序」問題。

**ICIR(IC Information Ratio)**
平均 IC ÷ IC 的標準差。衡量**訊號的穩定性** —— IC 高但忽高忽低,不如 IC 中等但穩定。
> 0.5 一般視為穩定。

**正 IC 比例**
所有交易日中,IC > 0 的日子佔比。50% 代表「方向對錯各半」= 純運氣;
70% 代表「七成的日子方向猜對」。

**預測期(Horizon)**
IC 計算時「未來 N 日」的 N。本專案測試了 5 / 20 / 60 / 120 日,
**發現 IC 隨預測期單調遞增 —— 這是本專案最重要的發現之一。**

## C. 回測與統計陷阱

**回測(Backtest)**
用歷史資料模擬「如果當時執行這個策略會發生什麼」。
**核心風險是各種形式的「偷看未來」,而這些偷看往往是隱形的。**

**前向測試(Forward Test / Paper Trading)**
不用歷史資料,而是**從今天開始,每天真實地跑一次決策並記錄結果**。
不能作弊(因為未來還沒發生),但需要時間累積樣本。
**本專案的七個帳戶自 2026-05-25 起連續運行,是驗證回測是否可信的基準。**

**Look-ahead bias(前視偏誤 / 偷看未來)**
在模擬「過去某一天的決策」時,不小心用到了那天之後才存在的資訊。
**這是回測最致命的錯誤,而且極難察覺** —— 因為系統不會報錯,只會給你一個好得離譜的結果。

本專案發現三個實例:
1. 用「資料庫最新日期」的股價算歷史淨值
2. 用「當前持倉」算歷史市值
3. ML 選股用「資料庫最新的評分」而非指定日期的評分

**Survivorship bias(倖存者偏誤)**
只用「今天還在市」的股票做回測,自動排除了曾經存在、後來下市的失敗者。
結果會系統性偏樂觀。
**解法**:建立 `universe_membership` 表記錄每檔股票的上市/下市日期,
回測時只從「當日真實在市」的名單中選股。本專案標記了 114 檔已下市股票。

**Point-in-time(時點正確)**
每個特徵都必須用「當時真的能知道的資訊」。
最常見的陷阱是財報與月營收:6 月的營收要到 7 月 10 日左右才公告,
若用「所屬月份」對齊,就等於偷看未來一個月。
**本專案的月營收採用「次月 15 日」作為保守的公告日估計,
且查詢一律用 `published_date <= 決策日`。**

**Walk-forward(滾動前推驗證)**
把歷史切成多段,用前段訓練/調參,後段驗證。
**目的是檢驗「優勢是否穩定」,還是只在特定期間有效。**
本專案用它推翻了自己先前的結論(見 7.3)。

**Purged / Embargo(淨化與禁區)**
當預測標籤是「未來 5 日報酬」時,相鄰兩天的樣本有 4 天重疊。
若用隨機切分做交叉驗證,訓練集會洩漏驗證集的資訊。
**解法**:用時間切分,且在訓練集與驗證集之間挖掉至少 N 天(N = 預測期)。

**重疊樣本(Overlapping Samples)**
120 日 IC 的相鄰觀測有 119 天重疊,彼此高度相關。
這會**低估標準差、高估 ICIR**。本報告已明確標注此限制。

**Curve fitting(曲線擬合 / 過度配適)**
在同一份歷史資料上反覆調參數,直到數字好看為止。
結果是「解釋過去完美、預測未來失效」。
**本專案的核心紀律之一就是對抗它** —— 任何參數改動都須開新帳戶前向驗證。

**隨機基準(Random Benchmark)**
用完全相同的架構(持股數、換手週期、費用)但**隨機選股**,重複數百次,
形成一個報酬分布。策略要贏過這個分布的 95 百分位,才能宣稱選股本身有價值。
**它回答的問題是:賺錢是因為選股厲害,還是因為架構本身(分散、低換手)?**

## D. 交易機制

**T+1 開盤成交**
本專案的成交模型:T 日收盤後產生訊號,T+1 日開盤價成交。
**避免「用收盤價成交」的不切實際假設** —— 你不可能在看到收盤價後還用那個價格買到。

**停損(Stop Loss)**
虧損達某比例時強制賣出。本專案設 -8%。

**停利(Take Profit)**
獲利達某比例時賣出。本專案設 +15%。

**到期換股(Max Hold Days)**
持有超過 N 個交易日就強制賣出並換股。本專案原設 20 日。
**經查證,此規則因錯誤 #8 自系統上線以來從未生效。**

**手續費與證交稅**
台股手續費 0.1425%(買賣各一次),證交稅 0.3%(僅賣出)。
本專案回測全額計入,且套用最低手續費 20 元。

**流動性限制**
單筆下單量不超過該股平均日成交量的 0.1%,避免「假設能買到不可能買到的量」。

**漲跌停鎖死**
台股單日漲跌幅上限 ±10%。鎖死時買不到或賣不掉。
**本專案回測尚未建模此情境,屬已知限制。**

## E. 資料品質

**僵屍列(Stale Rows)**
資料庫中「連續多日的收盤價與成交額完全相同」的列 —— 通常是抓取失敗時把前一日資料
複製過來造成的假資料。
**本專案 2023 年曾有 29% 的污染率(94,530 筆),重建後降至 2 筆。**

判別方式:連續 3 日的 `close` **且** `value` 完全相同。
(只比 close 會誤判 —— 冷門股價格不動但成交額會變,那是真實資料。)

**幽靈日期(Phantom Dates)**
資料庫中存在、但市場實際休市的日期。重建時採「先刪後插」可一併清除。

**除權息(Ex-dividend / Ex-rights)**
公司配發股利時,股價會在除息日「跳空下跌」約等於股利金額。
**若不處理,系統會誤判為虧損並可能觸發停損。**

- **現金股利**:配錢,除息日股價扣除該金額,持有者獲得現金
- **股票股利(配股)**:配股票,持股數增加、股價相應調整
- **權利歸屬**:除息日**前一交易日收盤**時的持有者才能領取

**還原價(Adjusted Price)**
把除權息與股票分割的影響還原,使價格序列連續可比。
例:0050 在 2025-06-18 進行 1 拆 4,股價從 188 變成 47,
若不還原,回測會誤判為「單日下跌 75%」。

**基準(Benchmark)**
用來對照的參考標的。本專案用三種:
1. **0050**(元大台灣 50):市值加權,前十大成分股佔比極高,台積電權重最大
2. **等權大盤**:全市場所有股票的平均漲幅 —— **對分散選股策略是更公平的對照**
3. **隨機組合**:同架構隨機選股,用於統計顯著性檢定

**為什麼要用等權大盤?**
0050 是市值加權,2023–2026 台積電漲 398%,幾乎主導了 0050 的表現。
拿「分散選 20 檔」的策略去比「重壓台積電」的指數,先天不公平。
等權大盤才反映「一般股票的平均表現」。

## F. 工程術語

**冪等(Idempotent)**
同一個操作執行多次,結果與執行一次相同。
本專案的補資料腳本皆設計為冪等,可安全重跑。

**自癒佇列(Self-healing Queue)**
抓取失敗時把日期登記到待補清單,之後可自動或一鍵補齊。
本專案有兩個:`pending_backfill`(股價)與 `pending_chip`(法人籌碼)。

**帳戶隔離(Account Isolation)**
回測帳戶使用 `account_id >= 100`,與前向帳戶(11–18)物理隔離,
且在決策鏈的每個函式加入帳戶範圍參數,防止回測污染真實實驗資料。

# 第三部 資料工程

## 3.1 資料源之戰(6/23 – 7/2)

**症狀**:連續多日 OHLCV 抓不到資料,pipeline 判定「非交易日」跳過,下游全部空白。

**第一個假設(錯誤)**:排程時間 16:30 太早,TWSE 檔案還沒出。
→ 改成 18:00,再改 18:30。**問題完全沒解決。**

**這次失敗很重要** —— 它推翻了時間假設,把調查方向轉向端點本身。

**真正的根因**:`STOCK_DAY_ALL` 端點持續回傳空資料。
法人資料(T86)走不同端點,一直正常,所以只有股價缺失 —— 這個「部分失敗」的模式
一開始誤導了判斷。

**解法(v1.2)**:

```
fetch_daily_all(date):
    df = MI_INDEX(date)              # 主源,支援歷史日期
    if df and len(df) > 800: return df
    df = STOCK_DAY_ALL()             # 備援
    if df: return df
    register_pending_backfill(date)  # 都失敗 → 登記待補
```

**意外收穫**:MI_INDEX **支援指定歷史日期**,而舊端點只能抓當天。
這個特性後來讓九年半的歷史資料重建成為可能 —— 從「逐檔抓 40 分鐘」變成
「一天一次呼叫、幾秒完成」。

## 3.2 兩層自癒佇列

法人資料的不穩定後續浮現(連續三晚 DNS 失敗),但它**不在原有監控範圍**。

增建 `pending_chip` 獨立佇列,並刻意採用**不同的補齊策略**:

| 佇列 | 監控對象 | 補齊方式 | 設計理由 |
|---|---|---|---|
| `pending_backfill` | 股價 | 重跑完整 pipeline | 股價缺失 = 當天什麼都沒發生,可完整重建 |
| `pending_chip` | 法人籌碼 | **僅補籌碼 + 重算評分** | 股價是好的、決策已發生,重跑決策鏈等於用已知後果改寫歷史 |

**這個區分是刻意的設計決策,不是簡化。**

## 3.3 九年半歷史資料建設

**起點**:資料庫只有 2.5 年,且 2023 年僵屍列污染率 **29%**。

**方法**:MI_INDEX 逐日抓取,**先刪後插**(同時清除幽靈日期),
進度寫入 `hist_rebuild_progress` 表支援斷點續傳。

| 階段 | 範圍 | 交易日 | 耗時 | 僵屍列變化 |
|---|---|---|---|---|
| v1.6 | 2017–2023 | 1,602 | 127 分鐘 | 2023: 94,530 → **2** |
| v1.8 | 2024–2026/5 | 575 | 42 分鐘 | 2024: 85,857 → **57**<br>2025: 71,303 → **42**<br>2026: ~24,000 → **7** |

**過程中的教訓 —— 隱形的空洞**:

第一次重建後發現 2019 年只有 231 個交易日(應為 ~245)。
追查發現:**抓取時遇到限流回傳空資料,被誤標為「休市」,而進度表會永久跳過該日。**

解法:把所有「休市」判定從進度表除名,重跑一次 —— 真休市的會重新標回休市,
被冤枉的則補回資料。一次修復了七年的空洞:

| 年 | 修復前 | 修復後 |
|---|---|---|
| 2018 | 235 | 245 |
| 2019 | 231 | 242 |
| 2021 | 240 | 244 |
| 2022 | 242 | 246 |

## 3.4 月營收:一道防呆檢查造成的三年資料缺失

**症狀**:`monthly_revenue` 僅 2,466 筆(合理值應為十萬級)。
2024 年只有 31 檔、2025 年只有 36 檔 —— 而台股有 1,800+ 家上市櫃公司。

**診斷過程**:
1. 確認端點可用(HTTP 200、43 萬字元、68 個 table)
2. 確認編碼處理正確(Big5 已妥善解碼)
3. 確認表格解析正確(手動測試可正確抽出「1201 味全 1799883」等資料)
4. **問題出在解析之後的一道防呆檢查**

```python
if len(html) < 500 or "404" in html.lower() or "查無資料" in html:
    print(f"[SKIP] empty")   # ← 正常資料被判定為錯誤頁
```

**根因**:`"404" in html` 用來判斷是否為 HTTP 404 錯誤頁,
但**正常的營收數字也含 404** —— 例如大成的當月營收 `8906040`。
所有上市公司頁面(數字多)被誤殺,只有零星上櫃頁面(公司少)倖存。

**修正後**:2022–2025 各年 12 個月完整、每年 2.2–2.4 萬筆、1,800+ 檔。

**連鎖效應** —— 這個缺失的影響遠超預期:

`scorer` 的 `fundamental_score` 依賴月營收。三年缺資料 → 該分項一直是預設值 →
`final_score` 尺度系統性偏低:

|---|---|---|
| 2023 | 35 | 0.15 檔 |
| 2024 | 79 | 0.33 檔 |
| 2025 | 368 | 1.5 檔 |
| 2026 | 4,428 | 31.6 檔 |

也就是說,**在歷史資料上跑 A1 的策略(min_score = 65)會幾乎不交易** ——
不是策略的問題,是分數尺度被壓低了。

補齊月營收並重算 2023–2025 評分後:

| 年 | 平均分 | 最高分 | 平均每日達標 |
|---|---|---|---|
| 2023 | 52.7 | 76.5 | 20.3 |

**四年尺度統一,歷史回測才成為可能。**

## 4.2 四個最重要的錯誤詳述

### 錯誤 #6 + #7:淨值計算的雙重前視

`update_v5_equity` 計算某日淨值時:

```sql
-- 錯誤版本
SELECT SUM(p.lots * o.close)
FROM positions p                          -- ← 當前持倉快照
LEFT JOIN ohlcv_daily o ON o.code=p.code
  AND o.trade_date = (SELECT MAX(trade_date) FROM ohlcv_daily)  -- ← 資料庫最新日期
```

**兩個問題**:
1. 價格用「資料庫最新日」而非該日
2. 持倉用「現在持有什麼」而非「那天持有什麼」

**為什麼潛伏三個月沒被發現?**
在每日正常運作時,「資料庫最新日」= 今天、「當前持倉」= 今天的持倉,**兩者都正確**。
只有在「回頭重算歷史淨值」時才會出錯 —— 而那正是回測要做的事。

**鐵證**:A1 的現金欄位在 5/29、6/30、7/31 三個時點完全相同(75,741),
但期間明明有十幾筆買賣。**整條淨值曲線的形狀是假的**,只有最後一天正確。

**修正**:改為從 `paper_fills` 重播出「該日收盤時的持倉與現金」:

```
該日持倉 = Σ(execution_date <= 該日的 BUY - SELL)
該日現金 = 初始現金 - 買入支出(含費) + 賣出收入(扣費稅) + ex_date <= 該日的股息
市值     = Σ(持股 × 該日收盤價,無報價則取該股最近一日)
```

修正後 A1 現金曲線恢復真實變動:61,667 → 99,930 → 75,741。

### 錯誤 #8:到期換股從未生效

```sql
INSERT INTO positions (..., opened_at)
VALUES (..., datetime('now','localtime'))   -- ← 寫的是執行當下的系統時間
```

持有天數的判斷是 `if max_hold and opened_at`。
- **回測時**:所有持倉的 `opened_at` 都是「跑回測那一刻」(2026-08),
  而回測日期是 2023–2026 → 天數算出 0 → **永不觸發**
- **前向系統**:既有持倉的 `opened_at` 為 NULL → 條件不成立 → **同樣永不觸發**

**也就是說「20 日到期換股」這條規則,寫在設定裡、寫在文件裡,但從來沒有執行過。**

修正後重跑回測,平倉次數從 100 → 193(幾乎翻倍),
回撤從 -26.4% 改善至 -17.9% —— **證明該規則確實有降低風險的效果**。

### 錯誤 #9:週五決策全部作廢

```python
next_day = SELECT MIN(trade_date) FROM ohlcv_daily WHERE trade_date > signal_date
execution_date = next_day if next_day else signal_date + 1天   # ← fallback
```

**週五晚上跑 pipeline 時**,資料庫裡最新的就是當天,`trade_date > 週五` 查不到任何資料
→ 掉進 fallback → `execution_date` = 週六 → 而成交模擬只在交易日執行
→ **該批決策永遠不會被執行。**

**實測影響**:2026-05-25 起共 6 個週五、**266 筆決策作廢**。

| 訊號日(週五) | 排到 | 決策數 |
|---|---|---|
| 6/05 | 6/06 週六 | 101 |
| 6/12 | 6/13 週六 | 31 |
| 7/03 | 7/04 週六 | 32 |
| 7/17 | 7/18 週六 | 23 |
| 7/24 | 7/25 週六 | 35 |
| 7/31 | 8/01 週六 | 44 |

**等於策略實際上只跑「週一到週四」。**

修正:三層防線 —— ohlcv → trading_calendar → 往後找第一個非週末日。
8/07 與 8/14 兩個週五皆驗證通過(正確排到下週一)。

**決定不回補那 266 筆** —— 前向實測是「系統實際做了什麼」的真實紀錄,
補執行會用到後見之明的價格,並使已封存的月度檢視報告失效。

回測引擎初期,`simulate_paper_fills` 未加帳戶過濾,

## 4.4 三個貫穿全程的工程教訓

### 教訓 1:「commit 成功 ≠ patch 生效」

7/24 套用籌碼監控 patch,終端機顯示「✓ 已修」、編譯通過、git commit 成功。
**但實際上 heredoc 在 zsh 中斷裂,程式碼從未寫入檔案。**
五天後因巡檢查詢報錯(表不存在)才發現。

**此後所有關鍵 patch 套用完必用 `grep -c` 驗證字串真的進入檔案。**

### 教訓 2:「背景任務啟動 ≠ 正在執行」

- 一次:長任務啟動後未驗證,Mac 睡眠導致中止,數小時後才發現進度停滯
- 另一次:指令因引號問題被 Ctrl+C 中斷,程序**根本沒啟動**,但誤以為在跑

**此後所有背景任務啟動後 30 秒必查進度是否推進。**

### 教訓 3:沉默的失敗最危險

月營收的 404 誤判、籌碼 patch 未寫入、淨值用未來價格、到期換股從未生效 ——
**這四者的共通點是:不報錯、不中斷、輸出看起來完全正常。**

系統會給你一個合理的數字,而你沒有理由懷疑它。

**若實際反而獲利,則代表回測與現實存在系統性差異,那本身就是重要發現。**

## 6.2 組合回測引擎

**核心設計原則:複用而非重寫。**

引擎直接呼叫前向系統的三個函式,只是餵入歷史日期:

```
for 每個交易日 d:
    generate_strategy_decisions(d, account_min=X, account_max=X)
    simulate_paper_fills(d, account_min=X, account_max=X)
    update_v5_equity(d, account_min=X, account_max=X)
```

**回測與實測跑的是同一套程式碼**,從根本上避免「回測結果 ≠ 真實行為」的風險。

**帳戶隔離**:回測用 `account_id >= 100`,決策鏈三個函式加入帳戶範圍參數
(預設值維持前向行為完全不變,經回歸測試驗證)。

# 第七部 研究發現

## 7.1 實驗一:換手頻率與分散度

**區間**:2023-01-01 ~ 2026-05-24(814 個交易日)
**方法**:同一套選股邏輯,只改架構參數,五組對照

| 帳戶 | 停利 | 到期換股 | 持股 | 報酬 | 回撤 | 平倉 | 費用 |
|---|---|---|---|---|---|---|---|
| 102 | +15% | 20 日 | 5 | +23.2% | -17.9% | 193 | 21,606 |
| 103 | 無 | 20 日 | 5 | +24.9% | -18.6% | 184 | 20,570 |
| 105 | 無 | 250 日 | 5 | +35.6% | **-37.0%** | 44 | 4,593 |
| **104** | **無** | **250 日** | **20** | **+105.6%** | -24.9% | 111 | 11,795 |
| 0050 | 買進持有 | — | ~50 | **+251%** | ~-20% | — | — |

**單變因分離的結果**:

| 改動 | 報酬變化 | 回撤變化 |
|---|---|---|
| 拿掉停利(102→103) | +1.7pt | 略差 |
| 延長持有期(103→105) | +10.7pt | **-18.4pt(惡化)** |
| **再加上分散(105→104)** | **+70.0pt** | **+12.1pt(改善)** |

**結論**:
1. **分散是主角** —— 貢獻 +70pt,且**同時改善回撤**,是投資中罕見的「免費午餐」
2. 低換手次之,但**單獨使用會惡化回撤**(5 檔集中 + 長期持有 = 押注運氣)
3. 停利影響極小
4. 主要傷害是「賣掉還在漲的贏家」,而非交易成本
   (104 費用只比 102 少一半,報酬卻多四倍)

**基準說明**:0050 的 +251% 需還原 2025-06-18 的 1 拆 4
(110.75 → 97.3 × 4 = 389.2)。同期台積電 453 → 2,255(+398%)。
**這四年是台積電主導的極端集中行情,任何分散策略都難以複製其表現。**

## 7.2 實驗二:隨機基準(500 次)

**問題**:104 的 +105.6% 是選股的功勞,還是「分散 + 低換手」這個架構的功勞?

**設計**:條件完全相同,僅選股改為隨機,重複 500 次。
**此設計刻意對策略不利** —— 隨機組合也享有最佳架構,架構的貢獻被扣除。

| 統計量 | 隨機組合報酬 |
|---|---|
| 最差 | -9.36% |
| 5 百分位 | 13.42% |
| 25 百分位 | 35.45% |
| **中位數** | **55.03%** |
| 75 百分位 | 78.67% |
| **95 百分位** | **119.73%** |
| 最好 | 360.08% |
| 平均最大回撤 | **-36.55%** |

**三個指標的對照**:

| 指標 | 策略 | 隨機中位數 | 隨機 95 百分位 | 策略百分位 | 顯著? |
|---|---|---|---|---|---|
| 總報酬 | 105.59% | 55.03% | 119.73% | 89.2 | ✗ |
| 報酬/最大回撤 | 4.24 | 1.51 | 3.82 | **97.0** | ✅ |
| 年化夏普 | 1.15 | 0.61 | 1.04 | **97.8** | ✅ |

**初步結論**:純報酬未達顯著,但**風險調整後兩項獨立指標皆達 97+ 百分位**。

**交叉驗證的價值**:「報酬/最大回撤」只看單一最壞時點,可能因偶然避開某次大跌而高估。
改用夏普(看整段路徑的日波動)驗證,結果**反而更高**(97.8 > 97.0) ——
證明低風險特質不是偶然,而是整段期間的波動都較低。

## 7.3 Walk-forward:推翻 7.2 的結論

**設計**:把區間切成兩段,各自獨立回測。

| 期間 | 策略 | 等權大盤 | 相對 | 回撤 | 平倉 |
|---|---|---|---|---|---|
| 2023-01 ~ 2024-12(481 日) | **+68.4%** | ~+43% | **+25pt 贏** | -18.5% | 58 |
| 2025-01 ~ 2026-05(333 日) | **-2.0%** | **+26.1%** | **-28pt 輸** | -21.8% | 83 |

**優勢不只消失,還反轉。**

而且後半段期間更短(333 vs 481 日),平倉次數卻更多(83 vs 58) ——
**換手率顯著上升但無法獲利。**

**7.2 的 97 百分位是全期間合併計算的結果,拆成子期間即不成立。**

這是量化研究中最典型的警訊:**完整樣本顯著、子期間散掉,
通常代表結果依賴特定市場環境,或含有運氣成分。**

**本專案最重要的自我修正:主動設計實驗檢驗自己的結論,並在證據不利時如實下修。**

## 7.4 IC 分析:訊號強度

**分年 IC**(final_score vs 未來 20 日報酬,871 個交易日):

| 年 | 樣本天數 | 平均 IC | ICIR | 正 IC 比例 |
|---|---|---|---|---|
| 2023 | 239 | 0.0111 | 0.19 | 59.4% |
| 2024 | 242 | 0.0253 | 0.35 | 62.4% |
| 2025 | 243 | **0.0040** | 0.04 | 52.7% |
| 2026 | 127 | **0.0284** | 0.31 | 63.8% |

**兩個結論**:
1. **四年 IC 全部 < 0.03**(業界門檻),ICIR 全部 < 0.5 —— 訊號微弱且不穩定
2. **訊號未持續衰減** —— 2025 是異常低點,2026 反而回升至四年最佳

因此 walk-forward 的績效落差**不是選股能力變化造成**,而是市場環境。

## 7.5 ★ 關鍵發現:訊號週期錯配

**測試不同預測期的 IC**:

| 預測期 | 樣本數 | 平均 IC | ICIR | 正 IC 比例 |
|---|---|---|---|---|
| 5 日 | 174 | 0.0063 | 0.06 | 57.5% |
| 20 日 | 171 | 0.0148 | 0.18 | 60.8% |
| 60 日 | 163 | 0.0274 | 0.37 | 66.9% |
| **120 日** | **151** | **0.0300** | **0.49** | **70.9%** |

**四項指標全部單調遞增,IC 增為五倍。訊號屬中長期性質。**

**而系統設計全面錯配**:

| 元件 | 現行設計 | 該週期的 IC | 問題 |
|---|---|---|---|
| ML 標籤 | 未來 5 日報酬 | **0.0063** | 在預測訊號最弱的週期,幾近雜訊 |
| A1–A6 換股 | 20 日 | 0.0148 | 在訊號發揮前就出場 |
| A8 持有期 | 250 日 | ~0.030 | **方向正確** |

**這很可能是 A7(純 ML)長期墊底的根本原因** —— 不是模型或特徵的問題,
而是**訓練目標本身就不可預測**。

**同時反向解釋了實驗一的結果**:104(250 日持有)大幅優於 102(20 日換股),
先前歸因為「低換手較好」這個抽象原則,現在有了機制性解釋 ——
**250 日更接近訊號的真實作用週期。**

**統計限制(誠實標注)**:長週期 ICIR 受重疊樣本高估
(120 日 IC 的相鄰觀測有 119 天重疊,標準差被低估)。
但 IC 本身與正 IC 比例不受影響,單調趨勢為真。
另須注意:即使最佳的 120 日,IC 也僅 0.030 —— **這是「有訊號」,不是「強訊號」。**

## 7.6 停損診斷

**追蹤 104 帳戶所有賣出後的股價走勢**:

| 賣出類型 | 筆數 | 後 20 日 | **後 60 日** |
|---|---|---|---|
| **停損(虧 >5%)** | **77** | +1.8%(上漲比例 47%) | **+11.0%** |
| 小賺小賠 | 5 | +4.9% | +4.9% |
| 獲利了結(賺 >10%) | 29 | +0.1% | +8.4% |

**停損砍掉的股票,之後 60 天平均漲 11%。**

個案佐證:

| 代號 | 停損損益 | 後 60 日 |
|---|---|---|
| 2383 | -9.4% | **+40.2%** |
| 4956 | -11.7% | **+30.0%** |
| 2359 | -8.9% | **+26.6%** |
| 2545 | -10.0% | **+20.9%** |

**短期看停損是對的**(20 日僅 +1.8%、上漲比例 47%,股價確實續跌),
**長期則完全翻轉。**

**但放寬停損反而更糟**:

| 帳戶 | 停損 | 報酬 | 回撤 |
|---|---|---|---|
| 104 | -8% | **+105.6%** | -24.9% |
| 108 | -15% | **+63.4%** | **-31.1%** |

**兩者可同時成立**:那 11% 的漲幅需要熬過更深的虧損才拿得到,而熬的代價超過收益。
**停損的價值在於限制單筆損失規模,而非避開下跌。**

**實驗限制(誠實標注)**:`stop_loss_pct` 在系統中**同時控制停損點與部位大小**:

```python
shares_by_risk = int(max_loss / (ref_price * stop_loss_pct))
```

放寬停損 → 分母變大 → 每筆買到的股數變少。
**因此 108 不是純粹的「停損放寬」,還混入「部位縮小」,無法乾淨歸因。**
此為系統設計缺陷,已列入待改項目(應將停損點與部位計算解耦)。

## 7.7 2026 的矛盾:選股有效,執行吃掉優勢

# 第八部 結論

## 8.1 對原始目標的回答

**「能否長期打敗 0050?」—— 目前無法證實。**

| 定義 | 結果 |
|---|---|
| 絕對報酬 | ❌ 四年 +105.6% vs 0050 +251% |
| 對照等權大盤 | 部分:2023–2024 贏 25pt、2025–2026 輸 28pt |
| 風險調整後 vs 隨機(全期間) | 97 百分位,但 walk-forward 後不成立 |

**根本限制**:選股訊號存在但微弱(IC 0.02–0.03),
弱到報酬主要由市場環境決定,而非選股能力。
2023–2024 的成功是「弱訊號 + 有利環境」的結果,不是可重複的 alpha。

## 8.2 完整的因果鏈

1. 選股訊號**有效但極弱**(IC ≈ 0.02;2026 選股贏市場 7.5pt)
2. 訊號太弱 → **報酬主要由市場環境決定**
3. 2023–2024 中小型股活躍 → 弱訊號 + 好環境 = +68%
4. 2025–2026 權值股獨強、等權大盤 +26% → 策略 -2%,落後 28pt
5. 停損砍在低點(77 筆,之後 60 日漲 11%),但放寬停損更糟
6. **且訊號是中長期的,而系統按短期設計** —— 這是最根本的錯配
7. **現有參數已接近局部最優** —— 改動任一項(停利、停損、持有期)都變差

## 8.3 有證據支持的改進方向

| 優先序 | 項目 | 證據 |
|---|---|---|
| 1 | **ML 標籤從 5 日改為 60–120 日** | IC 從 0.006 → 0.030,四項指標單調遞增 |
| 2 | **持有期匹配訊號週期** | 104(250 日)大幅優於 102(20 日) |
| 3 | **分散持股(20 檔以上)** | 貢獻 +70pt,同時改善回撤 |
| 4 | 停損與部位計算解耦 | 現行耦合使參數實驗無法乾淨歸因 |

**本階段不執行第 1 項的理由**:改動需重訓模型、重跑回測、開新帳戶前向驗證,
是完整循環,三週內做不完。**半套的改動比不改更糟。**

## 8.4 進行中的驗證

**A8 帳戶(2026-08-14 上線)** 是唯一「先有回測預測、再有真實驗證」的實驗。

**若實際反而獲利,則回測與現實存在系統性差異,那本身是重要發現。**

# 第九部 方法論反思

## 9.1 三個最有價值的機制

**1. 前向實測作為裁判**
七個帳戶自 5/25 起連續運行、規則零改動。
這條乾淨的曲線是回測引擎的驗收基準 —— **沒有它,就無法判斷回測是否可信。**

**2. 「重現已知結果」的硬檢查點**
規定引擎必須先重現前向曲線才能回測歷史。
此規則暴露了四個潛伏的 bug(#6、#7、#8、#9),
其中一個已存在三個月,另一個導致核心規則從未生效。

**它的真正價值不是驗證引擎,而是反過來稽核核心系統。**

**3. 隨機基準與 walk-forward**
前者回答「是選股還是架構的功勞」,後者回答「優勢是否穩定」。
**後者推翻了前者的結論 —— 而這正是它存在的意義。**

## 9.2 誠實的取捨紀錄

專案中有四次「主動放棄」的決定,均記錄在案:

| 項目 | 原因 |
|---|---|
| 歷史除權息回補 | 端點不支援歷史;缺口反推誤判率過高(2330 在 2023 真實除息 2 次,誤判出 10 次)。改採「不含息但公平」 |
| 歷史財報(fundamental) | 需逐檔逐季抓 MOPS,約 22 小時且格式不穩,投報比過低 |
| 266 筆作廢決策不回補 | 前向實測是真實紀錄,不是理想模擬。補執行會用到後見之明價格,並使已封存的月度報告失效 |
| 本階段不改 ML 標籤 | 需完整驗證循環,時間不足;半套改動比不改更糟 |

**放棄做不好的功能,比硬塞一個假地基有價值。**

## 9.3 對抗自我欺騙的具體措施

| 措施 | 防範的問題 |
|---|---|
| 前向實測規則零改動 | 事後調參、樣本重置 |
| 新實驗一律開新帳戶 | 污染對照組 |
| 硬檢查點(重現已知結果) | 回測引擎本身有 bug |
| 隨機基準 500 次 | 把運氣當實力 |
| Walk-forward | 環境依賴的假顯著 |
| 兩個獨立風險指標交叉驗證 | 單一指標的偏誤 |
| 帳戶隔離 + POLLUTION_GUARD | 回測污染實測 |
| 明確標注每個實驗的限制 | 過度解讀 |
| 數字特別好看時回原始資料驗算 | 錯誤 #1、#3 就是這樣發現的 |

## 9.4 未解與限制

- 回測不含息(策略與基準同樣不含息,相對比較有效,絕對報酬低估 3–4%/年)
- 未加入漲跌停鎖死建模
- 2023 年之前無法回測(缺該期間基本面資料)
- 2023–2026 為極端多頭,結論未必適用其他市場狀態
- IC 分析僅用 `final_score` 單一因子,未拆解六個分項各自的貢獻
- 配股(股票股利)未處理,誤差估計 < 0.5%/年
- `stop_loss_pct` 與部位計算耦合,使該參數的實驗無法乾淨歸因
- 前向樣本仍不足(最多的帳戶約 20 餘筆平倉),勝率與 PF 尚不具統計意義

## B. 核心原則

貫穿全程的工作準則:

- **誠實優先於好看的數字**
- **數字特別好看或特別符合期待時,更該懷疑**,回原始資料驗算
- **一次只改一個變因**
- **新實驗一律開新帳戶**,前向系統永不更動
- **趕不上就砍實驗範圍,不砍驗證機制**
- **commit 成功 ≠ patch 生效** —— 關鍵改動必 grep 驗證
- **背景任務啟動後 30 秒必查進度推進**
- **接受「策略可能輸給指數」或「好消息其實是 bug」的結論**
- **讓系統長期誠實運行,本身就是一種測試手段**
